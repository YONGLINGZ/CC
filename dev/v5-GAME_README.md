# 百妖夜契 · 寒渊问剑版

## 启动与操作

完整文件夹解压后打开 `index.html`，保留 `assets/`；单文件打开 `baiyao-standalone.html`。两者均离线运行，无需安装、服务器、登录或大模型 API。刷新会重新开始，暂不保存进度。

先选职业，再选起手流派。攻击、标记、霜寒等指定敌人的牌，点牌后点敌人；再次点同牌或按 Esc 取消且不扣费。无目标牌直接使用。每回合基础 3 灵力，抽 5 张牌，手牌最多 10 张；结束回合会展示并执行准确的固定敌人意图。牌堆、本局牌组、遗物和日志均可查看。

声画设置可以调音量、试听技能、选择快速／减少动态、关闭三维场景或夜铃动态立绘，查看所选角色的三态画卷。三态预览不修改游戏生命。顶部导出 HTML 保存完整单文件游戏，不保存当前这一局的进度。

## 两种职业

**夜铃 · 影契刺客**：成年猫妖，受雇入域寻找遗失契器。保留 36 张刺客卡与金瞳猎印、月影连爪、赤契噬魂三个开局。敌人标记最多 5 层，不自动增强所有攻击；扑杀与终夜消费标记爆发。金铃每回合首次实际加标记获得 3 护盾。连击与付出生命的策略均保留。

**沈霜白 · 霜华剑修**：太微剑宗成年女修，清冷少言，入域探查失踪同门。16 张专属冰剑技能形成独立牌池，初始遗物为霜魄剑穗。霜寒最多 4 层，使敌人下一次行动的每段攻击降低相应数值，最低为 0，行动后全部清除；没有攻击的行动也会消耗霜寒。界面即时显示减伤后的真实意图。剑意最多 8 层，跨回合保留；断流、万川归寂消费剑意爆发，回锋也能消费剑意换灵力。初始剑穗每回合第一次实际增加霜寒时，获得 1 剑意。

两职业的起始卡、战后选牌、重抽、事件授牌与商店商品按职业区分。共同遗物和秘宝可以共享，另一职业专属初始遗物不会混入精英奖励。剑修目前只有两张稀有牌，事件一次给两张稀有牌时会固定为碎霜与万川归寂，不把它描述成更多稀有种类。

## 背景与事件

玄烬教试图从归墟引来可供驱使的灵性，实验却把寒渊本身变成容器。黑雾隔绝外界窥视、传讯与占卜，区域中的道路与建筑开始失去原来的形状。各方只能派人进入，查探、寻人、收回证据或夺取异宝。终点为逆仪观测井，受侵蚀的绛鳞守在那里；这一幕只带出残页，不揭明雾中存在的最终真相。

四类势力通过背景及事件出现：太微剑宗、玄烬残众、千灯商盟，以及夜契盟与散修探客。没有加入复杂主线任务、声望或阵营养成。

14 类剧情奇遇是倒映祈愿井、无面旧神龛、卖梦人的摊位、纸灯戏台、雨夜借伞、蛇鳞当铺，以及封域望哨、断桥军需、逆仪残室、寒碑剑冢、失序行营、锁魂囚笼、异声裂隙、千灯密约。每次读前情、作选择、查看实际结局再前进；同一局优先抽未见事件。另有狐妖交易、商店和休息，全部具有独立事件画卡。

事件写明生命、最大生命、金币、删牌、卡牌和宝物变化。无法支付的选项不可用，处理后不能重领。剧情中提到的信息主要用于塑造背景，不把没有实际机制的描述伪装成额外收益。

## 路线、奖励与战斗

十段地图类型提前可见，只有实际连边可以选择。中段节点有一至两条出口，分叉、汇流和错过的支路有清楚区分；前三段后可规划精英、补给和事件，不能跳段、返回刷奖励或同时进入两个节点。固定战斗段防止一路奇遇直接到终点。

普通战奖励 20 金币与三选一卡；精英奖励 35 金币、稀有卡保底，以及两件未持有珍藏中选一件。首次精英保底出现秘宝候选。必须先选珍藏，再选卡或跳过。本局一次免费换牌，不能刷新金币或重复领取。珍藏、牌组、商店商品均真实生效。

护盾先挡普通攻击；毒与卡牌自损无视护盾。连段逐段结算，消耗只在本场离开牌堆，下场恢复；商店删除的是本局独立卡牌实例，下场仍然删除。休息恢复 18 生命，狐契付出 8 最大生命换一次免死。治疗不超过上限，死亡与胜利仅结算一次。

## 图像、音效和模型

52 种技能分别有独立画卡与离线程序音效，17 类事件场景、14 件遗物画卡、原有敌人画像保留。两位主角各有正常／战痕／濒危三张立绘，按当前最大生命比例在 50% 和 25% 含边界切换。治疗、毒、自损、免死和逐段攻击同步表现。

剑修正常图银灰长发、冰蓝眼、白蓝银纹长袍、持剑冷颜；战损加深时外袍破损、发丝与神态变化。刺客使用黑红金配色、猫耳尾和短刃。三维路线与角色由 `dev/scene.js` 的实际 WebGL 几何体生成，不加载外部引擎或模型文件；它们是低多边形场景原型。精细原画仍为主视觉，没有宣称完整商用 3D 角色或正式 Cubism 模型。

## 编辑与构建

规则数据在 `dev/engine.js`；UI 与演出在 `dev/ui.js`、`dev/shell.html`；离线声音在 `dev/audio.js`；三维场景在 `dev/scene.js`；夜铃 2D 动态在 `dev/puppet.js` 和 `dev/puppet-rig.json`；SVG 后备在 `dev/art.js`。资源由 `dev/build.cjs` 按规则中的卡牌、事件和遗物清单打包，不使用旧 `images.js`。

只在修改源码后才需要构建，使用 Node 标准库：

```sh
node dev/build.cjs --strict
node dev/build.cjs --strict --inline --output baiyao-standalone.html
node dev/build.cjs --slim --output /tmp/baiyao-slim.html
```

三种构建都无需开发服务器。无图模式使用 SVG 后备和程序三维几何。实际测试结果与未验证项见 `TESTING.md`。
