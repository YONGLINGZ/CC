# 天工院·陆听澜：机关小队角色设定与制作计划

版本：设计提案 v1.0｜2026-10-26  
代码核查基线：YONGLINGZ/CC main，825c47a0f5e5b5c2d9aca6e291df76095591c880。

本次交付完整角色设定、三具傀儡、资源与结算规则、48张独立技能牌、构筑方向、插画说明、资产清单、程序接入与分批验收计划。数值是原型初值，尚未实现到仓库，也未经过真人平衡验证。48张不包含基础操作按钮、傀儡自带指令、过载效果、升级版本或重复牌实例。

## 1. 定稿方向与核心选择

**陆听澜，27岁，天工院外勤机关师。她用操控丝指挥三具固定机傀，同时展开两具；在保留持续运转、主动指令和过载退场之间调度，自己也参加攻防。**

保留原案“本体与伙伴相互依赖、最后执行者接招”的特点，加入故障机器人式的“持续收益与即时兑现”。三具机体都拥有真实耐久、不同外形和受击风险，不能只当作三个无敌的光球。

推荐锁定以下决策：

| 问题 | 推荐实现 | 原因 |
|---|---|---|
| 同时几具？ | 总共三具独立机体，同时在场两具，另一具在机匣 | 三种两两搭配已经能形成选择；界面与维修负担可控 |
| 是否有同型号复制品？ | 首版每种唯一，不重复制造 | 玩家能记住它们，耐久、冷却与校准不会因为重新召唤而重置 |
| 灵力做什么？ | 支付卡牌、基础部署、替换与维修 | 保持现有每回合3灵力、抽5张的框架 |
| 是否新增资源？ | 只新增全队共用的“驱动” | 支付主动指令与过载；不再给每具机体加独立行动点 |
| 被动是否收费？ | 在场且完好的机体，结束玩家回合时免费运转 | 建立并保住机体能创造持续价值 |
| 主动兑现是什么？ | 过载：消耗驱动与耐久，爆发后退回机匣并冷却 | 立刻解决问题，同时放弃后续运转并付出重新展开的成本 |
| 能否修复损坏机？ | 可以，维修后下个玩家回合才能重新部署 | 让机体损坏有代价，也保留维修构筑的玩法 |
| 插画怎样换？ | 人物与机体独立图层，按机体状态切换 | 三套模型与人物三态独立组合，避免组合图数量膨胀 |

本方案取代旧案“傀儡一旦损坏本场永远失去”的规则。新版本允许付出灵力和等待时间将其修复。

## 2. 人物设定

### 2.1 身份、性格与目标

| 项目 | 设定 |
|---|---|
| 姓名 | 陆听澜 |
| 年龄 | 27岁，青春明快的成年女性 |
| 门派 | 正派“天工院”，负责护阵、桥梁、救援机关与民用机具 |
| 身份 | 外勤机关师，擅长现场抢修和协同机傀 |
| 武器 | 指环操控丝、折叠机尺、藏于袖侧的小弩 |
| 核心机具 | 三格便携机匣，收纳承山、鸣镝与拾萤 |
| 外在性格 | 活泼、反应快、喜欢动手；遇到新机关会眼睛发亮 |
| 内在性格 | 护人也护旧物，习惯先说“能修”；有时低估抢修需要的时间 |
| 优点 | 能在资源有限时迅速安排谁去做什么 |
| 缺点 | 不愿轻易放弃自己修过的机体，可能为保住它而冒险 |
| 出发目标 | 找回失联的救援队，调查护民机关被改造成杀器的原因 |
| 个人冲突 | 要证明机关可以保护人，也必须面对天工院的设计被滥用的责任 |

她的正派立场来自救人的职责。故事中可以质疑同门、公开证据，也可以因偏袒机体而犯错，不把她写成只负责讲道理的完美人物。

### 2.2 与三具傀儡的关系

- 承山原是护桥机兵。她保留了它胸口被小孩涂上的半朵红花，认为那比制式编号更好认。
- 鸣镝来自一具坠毁的传讯弩鸢。它的翼端刻度是她逐片校正的；她把“别往屋顶上扎”说成了口头禅。
- 拾萤最初只是修理灯，她给它加了夹手和收线臂，结果它成了最常替她收拾残局的小助手。
- 机体通过灯色、鸣声和简单动作表达状态，首版不引入三个会说完整人话的独立人格，避免对白与表情资产失控。

### 2.3 角色台词

选角：
> “别盯着我，你该防的是后面那个。”

开始战斗：
> “山子往前，鸣镝别飞太高——好，轮到我了。”

维修：
> “还能修。你先顶住，我就差这一颗销钉！”

驱动不足：
> “灵芯没攒够，这一招现在开不了。”

傀儡过载：
> “就这一回，出全力！回来我给你换新的。”

机体损坏：
> “线断了……别急，我还在。”

胜利：
> “人没事，东西也还能修。今天算赚了。”

这些对白配合动作与数值。规则仍直接写“获得2驱动”“恢复6耐久”，不用角色台词代替效果说明。

## 3. 资源、单位与操作规则

### 3.1 初始配置

- 角色初始生命：52，最大生命52，待测试。
- 灵力：每个玩家回合基础3，沿用现有下回合灵力与丹药规则。
- 抽牌：基础5，手牌上限10。
- 驱动：上限6，开战为2；从第二个玩家回合起，每回合开始自然获得1。未用驱动跨回合保留，战斗结束清空。
- 三具傀儡开局全部可用，不能把必需的召唤或维修方式锁进稀有掉落。
- 初始遗物“同心线轴”：战斗开始免费部署预设首发机体。默认首发承山，可在战斗外的机匣面板更换；不在每场弹出一次强制选择。
- 初始护卫为首发机体。之后由实际行动和退场规则改变。
- 初始10张牌：J01牵丝×3、J02护阵×3、J03并肩×2、J09展匣×1、J17注灵×1。
- 首版只提供一套起手，后续不同打法由选牌、遗物与机体搭配形成。

### 3.2 灵力与驱动的区别

**灵力是“这一回合能安排多少事”，驱动是“小队攒了多少可用于强动作的动力”。**

| 操作 | 灵力 | 驱动 | 结果 |
|---|---:|---:|---|
| 普通卡牌 | 按牌面 | 仅牌面写明时支付 | 可以由本体或某具傀儡执行 |
| 基础展开 | 1 | 0 | 从机匣部署一具可用机体 |
| 基础换机 | 1 | 0 | 收回一具在场者，在同位置部署一具可用备用机体 |
| 基础收回 | 0 | 0 | 收回机体，护盾清除，耐久不恢复，不返灵力 |
| 基础检修 | 1 | 0 | 一具机体恢复6耐久；若原为损坏，标记下回合才能部署 |
| 基础充能 | 1 | 0 | 获得2驱动；驱动已满时禁用 |
| 基础指令 | 0 | 2 | 使用所选机体的自带主动效果 |
| 基础过载 | 0 | 3 | 先付机体4耐久，再执行过载并退场冷却 |

所有操作都放在“机匣”控制栏内。它们保证角色可操作的底线；卡牌负责改变效率、联动与构筑方向。

每具机体每个玩家回合默认最多执行一次基础指令。卡牌明确写“额外执行”时可追加。计数按固定机体ID记录，收回、维修、再上场不会刷新。

每具机体每回合最多部署一次；免费首发也记录本回合已部署。其他机体仍可上场。换机、展开和相关卡牌都遵守此规则。过载机体本回合不能重返战场，最早在下一玩家回合重新部署。

机位已满时，展开操作必须先选择要收回的机体，再确认替换。普通收回和换机不会自动发动过载，也不会支付过载费用；取消选择不扣资源。

上述限制约束基础按钮，避免靠反复收回制造无成本刷新；不将所有卡牌联动一律限制为每回合一次。

### 3.3 傀儡是三具固定机体，不是无限生成的耗材

每具拥有耐久、护盾、所在位置、能否部署、当回合指令次数与本场校准状态。收回保留耐久和本场校准，清除护盾；再次展开不回满、不重置已用指令。

战斗结束时，三具机体在下一场恢复完整、清除本场校准与冷却；不将维修扩展成跨节点材料消耗系统。战斗之外不另收零件费用。

依靠现有修为等级做小幅耐久成长：本场最大耐久=型号基础耐久＋修为等级－1。修为目前上限6，所以最多增加5。只在开战时计算，不新增机体等级，也不自动强化运转、指令和过载数值。

### 3.4 护卫：保留最后执行者接招的特点

- 每张卡都标明执行者。只有有效且仍在场的单位，才能成为最后接招者。
- 本体执行卡牌、充能、基础展开、维修、收回后，通常由本体接招。
- 傀儡执行直接攻击、防御卡或基础指令后，由该傀儡接招。
- 卡牌注明“由某单位收招”时，以注明结果为准。
- 自动运转、被动追击、获得资源、状态结算不会偷偷改护卫。
- 用药不改变护卫。取消选牌、查看图鉴、调整音画也不改变。
- 当前护卫收回、过载或损坏后，自动改为本体，显示箭头转移。
- 护卫只分配直接攻击伤害；毒、追索印、封灵和少抽牌等效果仍按原规则作用于本体。机体不复制一整套人类异常栏。

使用一张牌前，预览除了伤害和费用，还显示“本牌结束后：由谁接招”。这是这个角色最需要看懂的信息。

### 3.5 受击、溢出与损坏

直接伤害先扣护卫自身护盾，再扣其耐久。某一段超出剩余耐久的部分继续打到本体，可被本体护盾吸收；后续攻击段也转向本体。

机体耐久归0时损坏，本体立即失去3生命，忽略护盾。这是操控线反馈。一般自损导致损坏也触发，只有卡牌明确写“免损坏反馈”才例外。

每次从正耐久降到0只结算一次损坏反馈；继续处理同一具已损坏机体，不反复扣本体生命。修好后再次损坏则属于新的损坏。

敌方一段攻击先完成机体扣耐久、溢出到本体与损坏反馈，确认本体仍存活，才处理相关反击。不会在本体已死亡后靠机体反击翻成胜利。

正常维修可以修损坏机，但它需要一整段等待时间：本回合从0修好，下一玩家回合才可部署。正在场上的受损机体修复后可以继续行动。冷却和部署次数限制不会因修复清除。

例：承山剩5耐久、4护盾，本体有2护盾，敌人攻击两次、每次6。
1. 第一段扣掉4护盾，再扣2耐久，承山剩3。
2. 第二段消耗承山3耐久，余下3打本体：2被挡，失去1生命。
3. 承山损坏，再反馈3生命伤害。本体本招合计失去4生命。
4. 承山进机匣标为损坏，下一回合花1灵力修到6，仍要等再下一回合才能重新部署。

### 3.6 运转、指令、过载：三个层次

- **运转**：在场机体免费提供的小收益。默认结束玩家回合时，从槽位一到槽位二各执行一次；卡牌可让它立即运转，不消费驱动。
- **基础指令**：支付2驱动的主动按钮，各型号不同，决定是否把动力用在现在。
- **过载**：支付3驱动和4耐久的退场式爆发。先扣耐久并结算可能的损坏反馈；本体若因此死亡，效果不发动。机体即便因这项代价损坏，只要本体仍活，预先登记的过载仍会发动。

过载专属卡写的是替代费用，不叠加基础按钮的驱动价格；4耐久代价与退场冷却仍执行。基础指令的额外执行也只有牌面明确写免费时免付2驱动。

过载支付代价后形成独立效果队列，不因机体损坏或退场取消；本体死亡或敌人死亡时停止。过载攻击引来的敌方架势反击优先打发动过载的机体；若它已经损坏，反击转向本体，可由本体护盾抵挡。不能用已损坏的攻击源吞掉反击。

不要同时增加热量、忠诚、零件、操控距离、三条独立能量或随机失控。耐久与位置已经提供了足够的机体差异。

## 4. 三具傀儡的定稿方向

表中所有伤害经过敌人护盾；运转伤害、基础指令及基础过载只吃本机明确调校，不复制人物的首段药力、血力或武器加成。

| 型号 | 承山·护城机兵 | 鸣镝·雷羽弩鸢 | 拾萤·提灯工蜂 |
|---|---|---|---|
| 基础耐久 | 18 | 10 | 8 |
| 外形轮廓 | 宽肩、粗臂、低重心，双掌折叠盾 | 长翼、尖头、细尾，悬浮的机关鸟 | 小灯腹、短翼、两只修理夹手 |
| 主色 | 旧铜、赭木、暖橙 | 青白、深蓝、少量银铜 | 暖黄、墨绿、乳白灵芯 |
| 默认运转 | 自身获得4护盾 | 对敌造成3伤害 | 获得1驱动 |
| 基础指令（2驱动） | 自身获得8护盾，本体获得4护盾 | 对敌造成7伤害 | 抽1张牌，下回合额外获得1灵力 |
| 基础过载（3驱动＋4耐久） | 本体获得18护盾，然后退场 | 连续造成3次、每次6伤害，然后退场 | 抽3张牌，下回合额外获得2灵力，然后退场 |
| 主要价值 | 保住前排，承受重击，支撑维修与反击 | 早期持续伤害，主动输出与多段爆发 | 维持驱动、手牌与下回合安排 |
| 主要弱点 | 本体接招时，它的自身护盾可能浪费；不能替本体挡毒 | 耐久低，负责接招时很容易受损 | 直接伤害和护盾少，贪资源会露出本体 |
| 过载代价 | 丢失前排与后续护盾，要重新安排护卫 | 丢失持续伤害与进攻核心 | 丢失持续驱动，未来可能无力继续发指令 |

三种组合的基本需求：
- 承山＋鸣镝：稳定攻防，适合初次上手。
- 承山＋拾萤：保机、修复与资源积累，需从手牌解决输出。
- 鸣镝＋拾萤：主动指令与过载更灵活，必须规划本体防守。

每个型号的基础运转保持单一用途。特色联动留给卡牌，以免初次看到机体就要读一整页规则。

## 5. 一个完整回合：资源与顺序怎样共同起作用

假设开战免费首发承山，2驱动、3灵力；本体及三机完好，没有额外增伤。

1. 花1灵力展开鸣镝，剩2灵力。展开动作由本体执行，暂由本体接招。
2. 花1灵力打并肩：本体6伤害，选鸣镝追击3；共9伤害，鸣镝接招，剩1灵力。
3. 花2驱动让鸣镝执行基础指令，造成7伤害。驱动归0，鸣镝仍接招。
4. 最后1灵力打护阵，选择承山：承山获得6护盾，承山接招。
5. 结束回合：承山运转再得4护盾，鸣镝运转造成3伤害。

结果：共造成19伤害；承山有10护盾负责接招；本体没有额外护盾。若敌人实际攻击9，承山不损耐久。下个玩家回合自然恢复1驱动，灵力重置3。

如果第三步后想继续抢输出而最后由鸣镝攻击，伤害可能更高，低耐久鸣镝就要面对敌人的反击。这是需要保护与调度的真实单位，而非只管叠加的被动图标。

另一个局面：本回合有3驱动、承山与鸣镝在场，急需防御。让承山过载能立即给本体18护盾，但承山先损失4耐久、退场，本体接招；下一回合还要付1灵力把它重新展开，期间也失去承山的运转。选择取决于眼前压力与后续手牌。

当前主游戏隐藏敌人下一招，上述敌伤数值用于解释结算，不表示玩家能提前知道。首版界面必须展示己方行动、护卫与可见敌方状态；是否全局恢复意图展示应另行对照测试，不能暗中捆绑到此角色更新。

## 6. 四种可混搭的构筑方向

| 方向 | 主要机体与牌 | 玩家追求 | 需要付出的代价 |
|---|---|---|---|
| 保机维修 | 承山、急修、不动榫、城墙回响 | 留住长期收益，用修复和反击打长战 | 灵力持续投入维修，短战可能输出不足，毒仍伤本体 |
| 指令协同 | 鸣镝＋拾萤、注灵、备用电池、双翼协作 | 用驱动增加主动行动，穿插普通牌 | 驱动有上限，机体脆，出牌后护卫可能不安全 |
| 过载轮换 | 三机切换、借位、山门不倒、雷羽齐发、万机归流 | 在关键回合兑现积累，换入第三具继续战斗 | 耐久损失、反馈风险、冷却与部署费用 |
| 持续运转 | 两具在场、灵弦、各型号校准、顺序调度、同心机匣 | 建立留在场上的持续输出、护盾与资源 | 需要时间与启动费用，过载会暂时拆掉已建立的场面 |

共同桥牌包括展匣、续榫、蓄电、卸力、放线追击、回收工序。它们应当让奖励推动玩家转向，不把四种方向做成开局互斥选项。

## 8. 卡牌功能密度、奖励与构筑验证

### 8.1 第一批12张原型牌

先实现J01、J02、J03、J05、J09、J11、J17、J18、J25、J33、J41、J47，共12张；三具傀儡与全部基础按钮同时可用。正式目标仍为完整48张，原型分批不删减最终内容。

这一批覆盖本体攻防、傀儡执行、换机、维修、驱动、过牌、三种机型特色和即时运转。随后加入校准、过载牌与能力牌，最后补齐其他桥牌。不要先画完48张卡图再测试资源是否成立。

### 8.2 选牌应随局面变化

- 鸣镝频繁受伤时，急修、盾行和收线的价值上升；不能只拿攻击。
- 驱动经常见底时，注灵、蓄电、拾萤与备用电池有用；经常溢出时应该考虑兑现手段。
- 拿到运转校准与同心机匣后，保住两机可能优于每回合过载。
- 拿到过载牌后，展匣、借位、维修与第三机的位置变得重要。
- 敌人反击多时，鸣镝自动攻击也会带来风险；面对持续毒与封灵，本体防护与状态处理不能被替代。
- 不拿每张奖励也应当合理。套牌越大，调度牌、充能牌和关键保护越难同时到手。

奖励仍采用角色独立牌池。初次测试不按“四流派”强制保底特定稀有，先给通用基础和桥牌足够出场机会。专属牌要求机型，但该机型开局已拥有，主要限制是战场安排与耐久。

### 8.3 对伤害、护盾与修为的约定

卡牌直接攻击复用现有伤害结算和首段增幅上限。J03、J38等一张牌包含本体与机体两段时，一次性首段增幅只给整张牌的第一段，不能每换一个执行者再领一次。

自动运转、基础指令和基础过载没有重复享受人物药力、血力、首张攻击遗物的资格。机体专属校准只修改注明的运转，不暗中修改另外两类效果。

卡牌型过载的伤害参数来自卡牌，按整张牌计一次首段增幅；其自损代价和退场也不能因为第一段击杀敌人而被漏掉，必须先支付。

本体获得护盾可沿用本体护盾遗物；机体获得护盾使用独立接口，不触发“你获得护盾”等只写给本体的遗物。某些未来遗物若作用全队，必须直接写全队。

首版不新增全卡升级系统。48张各有明确基础设计；未来升级只作为独立扩展，不计入48张，也不阻塞本角色的玩法验证。

## 9. 人物与傀儡插画设计

### 9.1 陆听澜主视觉

**画面关键词：青春、活泼、运动感、利落、手作痕迹、轻巧人物与沉重机兵的对比。**

| 部位 | 具体要求 |
|---|---|
| 年龄与面容 | 27岁成年女性，明亮眼神、自然脸颊与成熟骨相；表情是想到了办法的笑 |
| 发型 | 高马尾，带一小束不听话的鬓发；发绳朱红，护目镜可架在头顶 |
| 上衣 | 青灰短外衣，米白不透明内层，露臂；袖口有可拆的轻薄披袖，便于表现动作 |
| 腰身 | 朱红束腰、实用工具带，腰侧小幅露肤；线轴、销钉盒、折尺位置固定 |
| 下装 | 分片短外裙或短袴搭配内层安全裤；腿部线条清楚，适合蹲下维修和跨步发令 |
| 鞋 | 轻便短靴，鞋头略有磨损，脚踝与膝关节活动自然 |
| 手部 | 两手均有操线指环；一手引线，另一手可持折叠机尺。指头与线的连接必须能看懂 |
| 配色 | 青灰#4D7880、米白#E9E2D2、朱红#C95243、旧铜#A77C47，少量暖黄灵光 |
| 姿态 | 身体前倾半步，一手拉线一手向前指挥，重心稳定；有行动中的轻快感 |
| 小细节 | 鼻梁或脸侧少量灰痕，工具不洁净但保养好；随身挂着不对称的布签 |
| 构图 | 全身竖幅2:3，头顶与脚底留余量；手和控制线不被大机体遮住 |

青春感来自表情、动作、明快色块和主动性。正常立绘要看出她喜欢自己正在做的事。服装保留轻巧露肤与薄袖，不补成整身厚重盔甲，也不让工具带和首饰堆满身体。

正常、受伤、濒危三态保持同一人：
- 正常：笑着发令，线清楚、站姿灵活。
- 受伤：袖边破损、灰痕增多，表情认真；仍稳定握线。
- 濒危：单膝略沉、呼吸急促，一只手撑住机尺，另一手仍在指挥；表现疲惫与坚持。
- 三态不通过逐级脱衣区分。脸、衣装结构、线轴位置与画面锚点一致。

### 9.2 承山

- 高度约为陆听澜的1.5倍，宽肩、短颈、厚臂，有明显可开合榫卯。
- 胸口暖橙机芯，不使用骷髅脸；头部有像护桥兽的简化轮廓。
- 双掌与前臂可拼成盾，肘部粗大，腿部沉稳。
- 胸甲一侧保留小孩画的半朵红花，作为友军识别点。
- 正常图重心低而可靠；受损图呈现断裂护甲、露出支撑木骨；损坏图单膝落地、胸灯熄灭。
- 过载表现：盾形光幕扩成门，木铜本体仍是原机体，不变成另一个巨大角色。

### 9.3 鸣镝

- 机关鸟，轮廓细长，悬空高度约在少女肩部上方。
- 双翼由弩臂与薄铜羽组成，头部像箭镞，尾部有可活动平衡片。
- 青白与深蓝配色，电光只沿翼骨流动。
- 正常图双翼半展，能在窄屏完整显示；受损图一侧羽片缺失、电弧不稳；损坏图收翼落地、核心熄灭。
- 过载表现：翼骨先后张开，三道雷羽从同一机体射出，避免凭空出现三只鸟。
- 不设计成小剑堆，以免与剑修御剑混淆。

### 9.4 拾萤

- 体型约为少女上身一半高，灯腹圆而紧凑，有短翼和两只维修夹手。
- 暖黄与墨绿，白玉灵芯在透明灯罩内清楚可见。
- 有可转动灯头与收线臂；表情主要用光色表达。
- 正常图举灯，受损图灯罩裂一道、夹手不灵活；损坏图闭翼熄灯。
- 过载表现：灯腹分成三瓣，将动力送回公共机匣，仍保留明确机械结构。
- 不能仅画成一颗漂浮光球，关节和工具是其识别重点。

### 9.5 三机与人物如何同屏

- 人物固定在左侧主位，护卫傀儡可向前半步；其他机体保持后侧独立锚点。
- 承山偏后下方，鸣镝偏后上方，拾萤偏腰侧上方；敌人仍在右侧。
- 两具同时在场，不要求再出现一个巨大的“机匣实体”遮挡人物。备用机体用底栏缩略图表示。
- 手机竖屏：保持本体与当前护卫清楚，另一机体缩到后排小位；两张机体操作卡放到战场下方。
- 不依靠随机飞行和长动画区分机器人，减少动态模式也要看得懂。
- 操控线、护盾、充能光、弹道均为独立SVG/CSS效果，不烘焙在所有立绘里。

## 10. 插画生成流程、提示词与资产规模

### 10.1 制作顺序

1. 先画陆听澜与三机的概念板，确定比例、脸、服装、三种轮廓与色板。
2. 锁定一张陆听澜正常主图，作为后续编辑参考，不每次重新随机生一张脸。

## 11. 三段个人故事与现有Boss内容

不为新角色复制一整套七境地图。个人线提供三次稳定的相逢，其余仍使用现有路线、P2洞府与Boss任务。节点位置需要依据当前调度预留，不能覆盖已保证出现的关键任务。

### 11.1 桥口的旧机

一具停下来的护桥机关背着天工院编号。灾民认为它刚才踩塌了棚子，要求就地拆掉；陆听澜发现它的保险销被人为改过。

对白：
> 灾民：“你们造的东西，刚才差点把我儿子压死！”
>
> 陆听澜：“先带人离开桥墩。它现在不会动了，我把芯断开。”
>
> 灾民：“断开以后呢？再修好，接着压人？”
>
> 陆听澜：“我要查清是谁改了它。查不清，就不让它再站起来。”

选择：
- 花20灵石买替换件，帮忙稳定桥体。获得灾民证词，从J09展匣与J11急修中选一张；钱与牌奖励只领取一次。
- 就地拆除并回收材料。获得20灵石与损坏保险销，失去完整的机体记录；后续不写成已经完成修桥。
- 留下检查完整控制记录。获得另一种证据；现场追来的山魈会引发一场真实普通战，选项提前写明“调查后与山魈交战”。敌人使用现有ape定义与相应成长，不新增第四具可玩机体。
- 离去。不获得证据或牌，也不无故扣钱；主线仍能继续，但追责途径减少。

### 11.2 院里的封存令

天工院接应者要求将记录交回“内部核查”，并愿意提供机芯支持。对方担心公开不完整证据会让灾区再也不敢使用救援机具，也有保护院内声誉的利益。

对白：
> 接应者：“先把记录交给我。院里查清了，自然会给你答复。”
>
> 陆听澜：“保险销是按我们的图纸改的。把图纸给过谁，查一查就知道。”
>
> 接应者：“你现在拿出去，所有人都只会记得‘天工院机关杀人’。”
>
> 陆听澜：“那更该快点把真正动手的人找出来。”

选择围绕交回原件换资源、交副本保留证据、拒绝交易继续追查。可用材料取决于第一段事实，缺原件就不能伪造“交出完整原件”。支持可表现为下一场开始额外2驱动的一次援助；此项使用SVG物品图标，不增加必需原画。

### 11.3 该留下什么记录

末段取得足以确认改造责任的记录。既可以公开完整过程并承担同门关系代价，也可以交由院内追责换取制度性援助，或接受封口交易。选择不是“正派自动选正确项”，结果要回到具体的人与资源。

至少三种终局回应：
- 公开证据：救援队与受害者能说明责任链；部分院内人拒绝继续提供便利。
- 内部追责：保留院内支持，受害者会追问处理是否真的发生；后续须展示实际惩处或敷衍的区别。
- 封口交易：获得眼前资源，被救者或同伴得知后有明确失望回应；不再授予公开证词奖励。

三段事件的实际奖励和成本由配置生成文案；最终提交前锁定具体数值与一次性标记，不能只有不同结局标题。首版不添加新的“宗门好感分数”进度条，记录少量可解释的事实即可。

### 11.4 故宅机仆与P2互动

陆听澜可以识别故宅机仆的维修痕迹，提供额外观察和对白，但不凭职业直接跳过原有唤醒条件。备用铜匙、完整留声簧及真实任务记录仍须按现有规则取得。

面对阵营敌人，是否自动开战仍依据既有凭证与选择。不能因为她是正派，就把全部洞府改成友好。可新增“用技艺换情报”“修理救援装置获得证词”等真实选项，明确费用和所得，不重复领取原和平与战斗奖励。

- 耐久大于0且不高于50%：worn。
- 耐久为0：broken，仅在损坏瞬间战场短显，随后回机匣。
- 正常收回、过载冷却：底栏继续使用对应耐久缩略图，加上收纳或冷却标签，不新增一套全身图。

动画建议：
- 部署：120—220毫秒折叠展开与淡入，读数先按规则更新，动作事件顺序清楚。
- 收回：缩向机匣；不把尚未结算的技能特效一起删除。
- 换机：旧机收回、新机进入同一槽位，固定锚点，避免界面跳动。
- 指令：对应机体位移、光效与独立音色。
- 过载：先展示支付代价，再播放爆发、退场，最后切换护卫。
- 减少动态：直接切图，保留数值、名称和护卫反馈；不能改变规则。
- 加速模式：压缩停留，不丢掉多段伤害和反馈伤害。

切换图层必须由同一组战斗事件驱动，禁止CSS动画回调修改耐久、扣驱动或决定胜负。

### 12.3 不需要为每对组合重画陆听澜

如果把本体三态、三种两机组合、机体各自受损等状态一起烘焙成整图，很快会出现大量重复资产。分层后，3张人物图与9张机体图就能组合基本状态。

选角页可以使用“陆听澜正常图＋三机正常图”的独立排版，或做一张宣传合照作为可选资产；它不进入核心战斗切换逻辑。

### 13.3 单位结算接口

建议集中实现：
- 部署、收回、换机、修复、驱动获得与支付。
- 机体运转、基础指令、过载。
- 友方目标选择、伤害分配、损坏反馈、护卫更新。
- 本场能力与校准的触发登记。

“基础指令”只指按钮与明确写“执行基础指令”的卡牌效果。普通卡牌让机体攻击不自动算一次基础指令，不暗扣2驱动。

机体伤害仍走敌人现有护盾、免死、阶段保护与胜利接口。敌方架势反击针对实际攻击执行者：本体攻击打本体，鸣镝攻击或自动射击打鸣镝；机体因此损坏仍结算反馈。不能把所有反击都悄悄转给当前护卫。

J32城墙回响只响应敌人主动直接攻击造成的耐久损失，不响应架势反击、过载自损和其他自损。反击源不能递归触发敌方同类反击。

敌方按本体生命伤害吸血的既有规则只统计本体实际损失，机体耐久不算血肉生命；不能因为转移伤害而漏记本体溢出部分。若某种具体敌招需要“吸取机关灵能”，应单独设计并在牌面显示，首版不偷偷增设例外。

### 13.4 推荐回合时序

1. 玩家提交结束回合，锁定输入，处理现有弃手牌。
2. 按机位顺序执行自动运转，这是玩家回合尾的最后一段。
3. 每个效果都检查本体／敌人是否已死亡；鸣镝被反击摧毁也结算反馈。
4. 然后按原流程锁定敌方行动、处理敌方起始状态、冻结与招式；新增机体逻辑不能重新抽取下一招。
5. 每段直接伤害由护卫分配，处理护盾、耐久、溢出、反馈与允许的反击。
6. 玩家回合开始清理本体与在场机体护盾，处理既有状态和资源队列。
7. 刷新当回合可用状态，更新冷却；灵力、驱动与抽牌按统一接口给出。
8. 更新界面。读取与预览不运行真实运转、不消费随机数。

涉及复仇阈值等原有边界时，自动运转属于玩家回合尾，因此应在敌方最终行动锁定前完成。旧角色无小队时，不额外调用随机函数，也不改变原有结果。

## 14. 制作批次、交付物与验收门槛

### 批次一：规则与灰盒

交付：三机、两个机位、灵力／驱动、护卫、指令／运转／过载、损坏／维修、12张原型牌。使用可识别色块和名字，保留资源与伤害日志。

验收：
- 3种两机组合都能真实完成一场普通战。
- 正常展开、换机、收回、过载、重启有不同成本。
- 最后一手能改变谁接招，预览与实际一致。
- 没有抽到召唤或维修牌也能操作角色。
- 所有机体损坏时，本体还能用起手攻防和基础检修继续战斗。

### 批次二：验证资源和构筑

交付：加入各型号校准、能力与过载牌，达到24张；其余24张规则表仍保留。

使用可复现遭遇比较：持续攻击、多段攻击、纯施术、反击架势、护盾型敌人、毒与资源压制敌人，以及固定轮转Boss。

验收：
- 不会每回合都机械地按完两个指令再结束；玩家需要根据驱动储备与最终护卫决定是否使用。
- 保留机体和过载都有合理使用场景。
- 拾萤不会成为全部牌组无条件必带。
- 承山不只是额外18血，鸣镝不只是每回合自动打3。
- 除驱动外，没有因补漏洞继续增加新的资源条。

### 批次三：人物、机体与战场

交付：陆听澜与三机概念定稿、人物三态、三机九图、机匣／遗物、真实桌面与手机布局。

验收：缩小后仍能识别三机；护卫一眼可见；受伤和冷却不会被误认为死亡；换机不替换人物脸；透明边缘与遮挡通过检查；减少动态模式可正常理解过程。

### 批次四：完整48卡与卡图

交付：48张规则完整接入、48幅独立卡图、图鉴、稀有度与奖励过滤；69张基础导出资源齐全。

验收：
- 48个唯一ID和唯一名称，只有基础牌不入普通奖励。
- 每张卡都有费用、执行者、目标、效果、失败条件与图。
- 有驱动费用的卡在不足时不扣灵力，不产生半截效果。
- 动作失败因对局中途死亡时遵守规则，而非事后返费。
- 直接伤害、被动、指令、过载在加成和反击上分得清。

### 批次五：个人线与世界回应

交付：三段事件、三张场景图、回访与结局；与故宅机仆、P2凭证和援助兼容。

验收：证据有真实来源；交易、调查、拆除、救人和离去产生不同事实；无见过前段却自动称救过人的台词；职业不越过原有关键任务条件。

### 批次六：回归、真人体验和发行

交付：规则测试、浏览器交互与性能记录、真实试玩问题及修正、目录版和单文件版一致构建。

正式构建使用当前脚本提供的node dev/build.cjs --all；在临时输出或独立检出完成，不覆盖用户未提交工作。原型可使用脚本现有的--slim与--output选项。必须执行项目当时真实存在的回归，不凭文件名虚构通过记录。

未完成真人体验时，TESTING.md继续标注待验证；规则单测、资源齐全与可达性不等于“已经好玩”。

## 15. 关键验证清单

| 类别 | 必须覆盖 |
|---|---|
| 资源 | 首回合驱动不多发；第二回合自然恢复；上限溢出；替代过载费用不重复扣；取消选择不付费 |
| 单位 | 每型号唯一；满槽不自动覆盖；换机不回满耐久；同回合换出换入不刷新指令 |
| 冷却 | 过载当回合不可重返；损坏修好后的下一回合才能部署；反复维修不提前解除冷却 |
| 护卫 | 本体、承山、鸣镝、拾萤各接招；多动作卡最终执行者；自动运转不改护卫；退场回本体 |
| 伤害 | 单段溢出、多段中途损坏、本体护盾抵溢出、反馈无视盾、反馈致死、反击不递归 |
| 过载 | 先付耐久；耐久不足4仍可损坏爆发但要反馈；反馈致死不发动；已损坏机体的过载反击转打本体；卡牌型过载费用与属性准确 |
| 运转 | 槽位顺序；反击致死停止；运转击杀只发一次奖励；即时运转不额外收费、不改变护卫 |
| 现有状态 | 毒、追索印、封灵、少抽牌仍作用本体；冻结不取消已发生的己方运转；援助只消耗一次 |
| 48卡 | 两机选择、多目标顺序、重启、手牌上限、能力叠加、未在场机的校准、无合法目标禁用 |
| 随机与预览 | 面板、悬停、切图、动画和选中取消不改变随机序列；预览不泄露下一招 |
| 资产 | 正常／受损／损坏选择正确；人物三态独立；所有组合与移动端尺寸可读 |
| 旧角色 | 夜铃、剑修、绯夜、晏绮罗的起手、遗物、伤害、卡池、图鉴与结局不被新字段污染 |
| 发行 | 目录版、单文件、图片数量、资源缺失检查与版本号一致 |

真人先观察5—8名不同熟练度玩家，用于发现明显问题，不据此宣称平衡已成立。记录：
- 第一场结束能否解释灵力与驱动的区别；
- 能否预判最后谁接招；
- 是否主动修机、换机或过载，而非只用一套组合；
- 是否知道“收回不修复”“过载先伤机体”“破损反馈伤本体”；
- 何时驱动不足、溢出，哪些卡改变了这一点；
- 选到不同奖励后，是否真的改变保机与过载的倾向；
- 操作耗时、误点、读规则的停顿与想再玩一局的原因。

## 16. 首要风险与调整顺序

1. **机体成为无脑额外血条。**先观察损坏频率、反馈、重新展开与修复成本，以及保存机体能带来的输出价值；不要第一反应再加材料条。
2. **拾萤提供资源过于重要。**比较有无拾萤的驱动缺口；调整自然恢复、充能卡与拾萤数值，保留承山＋鸣镝的可行性。
3. **自动伤害取代玩家出牌。**调整运转与主动输出比重，确保行动顺序和卡牌组合仍决定表现。
4. **全部都过载最划算。**检查再部署、4耐久、护卫转移、校准收益和冷却是否真的形成成本。
5. **专属牌太多导致卡手。**已有三机可用，仍应检查所需机型常不在场的频率；增加通用桥牌、调整奖励比例或重写个别技能，不能只让玩家硬背套路。
6. **界面太挤。**先保证两个机位和护卫信息清楚，减少装饰与无关状态；不继续扩大同时在场数量。
7. **现有隐藏意图使风险难估。**观察玩家是否只能固定保守出牌；另做意图信息对照，避免给角色叠加随机失控制造更多不确定性。

优先顺序：先让三机小队与资源循环成立，再完成48卡功能密度，再投入完整插画和剧情。最终交付目标始终是本文件的三机、48卡和69张基础导出资产。
