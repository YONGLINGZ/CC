# 侧幕交锋 · 2026.11.04-review.5

基线：GitHub main `08a6e9932777896deead59b482c4b43d26d2b757`。本轮分支 `improve/side-stage-v5`，仅本地修改、构建、验证与交付；不推送、不部署。

## 我的判断

更适合本游戏的是“侧视角色舞台＋原有回合制卡牌”。小人负责表现谁出手、谁接招、命中与防守；卡牌与资源栏继续负责决策。保留藏招的敌方攻击前/整招结束后两个时机、观息的精确信息价值和机关师的执行者/接招者机制。此时加入实时走位或距离数值，会改变所有牌的价值和敌人平衡，因此本轮没有这样做。

这是参考用户提出的侧视交锋与清晰卡牌反馈所作的独立实现，未使用《太吾绘卷》《杀戮尖塔》的图片、角色、代码或动画素材。是否更好玩仍需自然长局反馈；自动化不能替代玩家审美与决策体验。

## 实际改变

- 将战斗用大立绘改为原创 SVG 分部件角色。五位主角分别保留猫耳尾爪、长发霜剑、绡骨扇、机关匣、冠饰月魄特征；原立绘保留为身份小图。选角、故事、图鉴的原画不变。
- 左右对阵并同地面站立。名字、生命、护盾独立于小人下方；Boss 尺寸略大。同名敌人的身份小图独立于玩家战损状态。不同 Boss 使用灯、结、钟、机关、月、火、面具、符印等道具；普通敌人复用骨架，按类携带道具，保留原画与名字辨识。
- 头部、衣摆、尾部待机；手臂、双腿、躯干独立动作。10 种出手姿势＋1 种受击姿势，覆盖挥斩、突刺、跃击、移步、引导、牵引、俯身、护守、舞步和献祭。
- 为现有全部 **180 张战斗卡**逐张写入演出配置：C36、S36、D12、F12、H36、J48。使用 **44 种原创矢量图形**，组合姿势、颜色、角度、粒子数与施放/命中时机。完整逐卡表见 `CARD_PRESENTATIONS.csv`。
- 这是180套参数化演出配置，不是180段独立手绘动画。相近技能会共享骨架与图形；部分差异较细微。装饰粒子数量不是伤害段数；真正的命中特效只跟随规则中的 attack 事件。
- 藏牌只在自身表现准备，不能提前向敌人显示命中；触发时重新选择该藏招的卡牌配置。机傀攻击沿用实际 executor，连续伤害逐段播放；未绑定战斗卡的自动攻击保留通用效果。
- 完整、快速、减少动态、仅数值四种模式。系统减少动态偏好生效；切换关闭时立即取消舞台关节动作。动画不写入存档、不修改游戏状态，原有忙碌锁防止连点重复出牌。新装饰特效最多同时8个，自动回收。

## 验证方式与证据

这是浏览器 UI 测试和规则回归，不是新玩了十局。

- 完整规则回归614项：原有610项＋本轮4项覆盖注册表、骨架与纯表现边界。游戏规则模块未改。
- 真 Chromium 按钮逐张使用180张牌，核对出牌成功、配置出现、每个实际攻击对应一个新命中特效、机傀执行者与目标一致、结算结束无残留特效。
- 五职业×九种敌人/Boss×1440/360/390/430 CSS像素，共180组布局：小人不被状态框覆盖、不出舞台边界、无页面横向溢出、原画小图等比。
- 五职业真实出牌及敌方回合验证关节动作与受击；观看了桌面、窄屏、出手截图。截图保留评审环境，不包含在交付包。
- 原有合欢浏览器13组、机关师9组回归通过；原来的“大立绘必须占满框”断言更新为“原画身份小图＋可见的舞台骨架”，没有删除画面验证。
- 补测藏招前后顺序、双击只出一张、途中关闭动画、装饰特效上限、离线单文件加载与触摸模拟入口。最终压力采样90帧，中位16.7ms、95分位17.1ms，最多8个特效，结束残留0且游戏状态完全不变；这不是低端设备帧率保证。结果见 `edge.json`；浏览器逐卡证据见 `browser.json`。
- 测试为显式可控夹具：会准备角色、血量、能量、手牌和敌人以覆盖边界，不将这些测试宣称为正常通关或自然胜率。初次脚本遇到魔修未习得、驱动已满、合击缺第二机体等非法夹具，按规则补齐前置后重新运行；未放宽游戏规则。

## 真实局限

1. **不是 Live2D/Cubism**。是原创程序化关节小人；没有专业分层原画、蒙皮、表情捕捉或逐帧手绘。几何风格仍较简洁，不能声称达到两款参考游戏的美术完成度。
2. 五职业有区别，但62种敌人没有62套独立骨架。Boss主要依靠轮廓、道具、大小、名字与原画小图区分；机傀继续使用已有图片和整体运动，不是全新机械骨骼。
3. 180张都已接入配置和出牌验证，没有未配置的卡；同一类牌仍会有相似感。合欢直接使用/藏招触发共享该牌主题，分别由实际时机调度，没有额外制作36段独立藏招手绘动画。
4. 只验证了云端Chromium与触摸/窄屏模拟，未声称实体手机、Safari、Firefox、低端GPU均流畅。性能采样只代表本环境。
5. 保留原来的卡牌滚动和角色机制面板；手机上机关师与合欢仍需要上下查看机制与手牌。下一步应根据用户实玩反馈决定是否将这些面板收纳为可展开摘要，而非现在隐藏关键决策。
6. 数值、敌人难度、复活任务、奖励、存档结构没有调整。本轮不声称解决所有玩法平衡问题。

## 使用

完整包由多个**独立标准 ZIP**组成，每个低于20MB，不是`.001`分卷。把全部 ZIP 解压到同一位置，得到一个 `baiyao-review-v5` 文件夹，然后打开其中 `index.html`。不能只解压第一包；每个包里的文件互不重复。游戏运行不需要联网。

该目录包含现有图片资源、当前完整构建源码和测试，`node dev/build.cjs --all` 可重新生成目录版与单文件版。为避免重复传输104MB的内嵌成品，分包只携带目录版；内嵌版已在本地构建并浏览器检查。未包含巨大历史恢复包和浏览器截图；它们不是运行所需资源。合并解压与重建一致性见交付清单。
