# 知势择路：十局评审后的第一版改进

版本：2026.10.31-review.1。基础提交：07f963a94018f51e36b253cceb8e1b289364fd98。工作分支：improve/player-review-v1。

开始实现前核对远端 main，仍与十局评审版本一致；工作区干净，没有覆盖其他人的后续改动。本版是本地改进版，未推送、合并或部署。没有新增角色、卡牌或事件数量。

## 已实现

### 1. 修正三项会破坏玩家信任的问题

- 共享人物事件承诺“对应主角功法”时，陆听澜现在取得机关师的「袖弩」J07，不再回落到刺客「追猎」C18。其余四角色映射保留。
- 命枢和心影的纯调查路径，不再出现“按自己签过的空符”等误认签约的行动名。调查仍只核对记录，不会凭空领取需要本人决定的援助。
- “本境镇境之战护身符”在作出选择时绑定本境实际镇守，包括旧宫故事发生在第七境、最后却面对归墟司命的情况。只修正这张10盾护身符的目标；人物专属旧物证、抵消异术与额外8盾仍按各自目标结算，不把旧宫所有奖励都转给最终Boss。
- 额外清理：空的剧情赠牌数组不再生成没有内容的“新得经页”标题。

### 2. 给攻守判断提供线索，保留观息优势

所有角色现在看到“攻势将至／蓄势施术”和粗略强度：当前直接攻击总量低于10为轻缓、10–19为明显、20以上为猛烈。普通提示不公开准确伤害、段数、招式名称或具体异术；不攻击也不等于安全。

合欢观息升级为查看当前攻击段数、伤害与异术。每战三次、每回合一次的限制不变。观息内容随当前状态变化；藏招、一次性阵营援助等仍在行动时结算，提示明确注明这一边界，不承诺“最终必受多少伤”。读取提示不会重新掷敌招或消耗随机数。

双时机藏招、两槽、机体驱动与接招规则、剑意和魂息系统均保留，没有把角色简化为同一种攻防。

### 3. 把战斗操作区收拢

- 缩短战斗舞台与卡图高度，保留角色画面、敌人生命和护盾；旧事、随身约定移到可展开区，仍可查看。
- 移除战斗手牌固定490像素高的限制，让规则内容决定高度；完整卡面规则不截断，横向滚动查看更多牌。
- 资源栏和结束回合工具栏在滚动时保留，工具栏根据实际资源栏高度定位。
- 机关师机匣紧凑显示耐久、护盾、运转与指令状态；窄屏横向查看三机。确认施术旁明确显示本次执行者与结束后的接招者，取消不扣资源。
- 合欢的观息、两个藏招槽和资源集中在出牌区上方。

这不是“所有牌、所有机体在手机一屏全部展开”。长规则和更多手牌仍需滚动。当前测试覆盖360、390、430像素宽度；未宣称320像素或实体手机已通过。

### 4. 减少白走节点，给资源留下取舍

休息点增加“整备护符”：放弃本次治疗，换取下一场战斗首回合8护盾，触发后清空。治疗、调脉和直接离开仍可选择，同一个休息点不能重复领收益。满血时不再只剩恢复0血。

商店增加10灵石换货：每次到访仅一次，只更换未售出的技能，已购商品、牌组、武器与药品不刷新；新技能排除原货架上的技能。灵石不足或没有未售技能时不能支付。它提供一个花钱寻找构筑牌的机会，不是无限重抽。

### 5. 适量调节拖延与通用强奖励

逆仪祭司基础生命92→80；逆祝由恢复8、护盾8改为恢复4、护盾5。它仍有祭仪加盾/追索印和咒刃，原有行动权重与不连续重复规则保留。没有统一下调所有敌人或删除防守招式。

梦匣首回合仍加1灵力，额外抽牌2→1；残月坠仍抽2张。两者可叠加，但梦匣不再同时完整覆盖残月坠的抽牌量并白多一费。月髓、玉髓和其他遗物本版未继续削弱，避免一次更改过多变量。

## 实际验证

### 规则与构建

- `node dev/v11-regression.cjs`：587/587规则检查通过，原有检查保留；其中新增7组专门覆盖职业奖励、调查路径、准备目标、提示信息边界、休息互斥、换货支付与空奖励。
- 两个既有数值断言随祭司调整更新，梦匣断言随新抽牌量更新；没有为了过关删除测试。
- 严格构建目录版与完整内联单文件，所需运行素材齐全。
- 固定旧策略150局：127胜、23败；隐藏路线24局：16胜、8败。它们是自动规则探针，可读取内部信息，不是新一轮人工试玩。既有平衡门槛仍未全达标。

### 实际Chromium按钮检查

- 五角色核心操作＋休息/商店新动作：6组通过。使用明确标注的角色、手牌与战斗夹具，实际点击出牌、选敌、观息、藏招、机关师确认和结束回合。
- 合欢及原有角色专项：13/13通过，包括双模式、两槽、观息限制、个人场景、技能与目录、窄屏及单文件内容检查。观息测试已按新语义检查细节展示；版本断言读取发布配置。
- 机关师专项：9/9通过，包括执行/护卫预览、取消、换机、驱动不足、过载维修、窄屏44像素控件和机体状态。
- 布局对照：五角色×四种宽度×旧/新两版，共40个布局样本；新版20个样本无页面横向溢出，敌人生命条未被舞台裁掉。横向手牌/机匣滚动是有意设计。
- 两个祭司长战浏览器样本完成，详见下表。它们是固定种子、明确测试牌组的按钮策略，不是自然整局。
- 另手动按可见界面完成夜铃一场正常开局战斗，3回合胜、59/60生命。没有修改该场血量、手牌或敌人来凑结果；它不是一次完整七境通关。本轮没有声称又玩了十局。

### 离线交付检查与限制

完整单文件约104.2MB，含内联素材。通过本机HTTP加载单文件，阻断除此文件外的所有HTTP(S)请求后，实际点击开局进入战斗，敌情提示正常，零脚本错误、零额外网络请求。

直接访问file://在加载前被云浏览器管理员策略阻止。因此未把“双击文件已实测”写成通过；产品仍使用离线内联脚本/素材，不需要服务器服务、账号或API。真实手机、Firefox/WebKit、音频人耳听感和新版本自然十局胜率未测。

## 交付内容与启动

- `baiyao-review-v1.zip`：完整解压后打开其中的 `index.html`，保留同级 `assets/`。包含本说明、规则文档、源码、测试及本轮文字证据。
- 仓库根目录 `baiyao-standalone.html`：完整内联单文件，可单独复制保存。为避免重复下载约100MB数据，ZIP使用目录版素材结构。
- `docs/review-v1/verification.json`：版本、源文件SHA-256、规则总数、前后指标、浏览器结果与布局样本。
- `docs/review-v1/text-evidence.zip`：本轮文字回执与探针结果，不含浏览器截图。截图保留在评审环境作验证。

附件只有在上传返回真实成功结果后才算交付；本地路径本身不是用户可下载附件。最终对话另行报告上传状态。
