# 2.1追加复核：门禁、剑修与续灯时限

本报告针对2026.11.02-review.2的未达标项。成品版本为2026.11.02-review.2.1，保留原难度数字，不为达到某个统计阈值继续降Boss血量或增加角色基础属性。新增可复现的策略对照、任务截止检查和界面说明；仍只本地提交，不推送。

## 四项未通过门禁及其依据

|原门禁|阈值|旧策略当前结果|处理与依据|
|---|---|---|---|
|胜局剩余生命中位数|15—25|36|保留未通过。只统计幸存者，且最大生命会成长，不能单凭这一项认定后期太简单，更不能为了降低残血惩罚胜者。需要连同死亡率、归一化生命和战斗损耗看。|
|各职业胜率|25%—75%|夜铃74%、剑修24%、绯夜58%|保留未通过。剑修12/50只比下界少一胜，但相对基线31/50明显下降，因此必须继续定位，不能改阈值掩盖。|
|全局最强单击中位数|≤34|49|保留历史失败记录。阈值是早期校准目标，现有剑意/猎印终结技本来就能超过34，S16满剑意基础56；真实规则要求是额外首段增幅上限8，相关测试通过。不能为此把不同流派终结技全部削成同一伤害。|
|Boss战中位长度|8—14回合|6|保留历史失败记录。混合了七境和不同Boss，没有真人节奏依据证明每场至少8回合才好玩。当前剑修致死Boss战常为8—10回合，继续加血可能加重问题。|

这组阈值来自仓库v11校准脚本和历史测试目标，不是用户确认的验收标准，也不是由玩家样本拟合出的统计标准。本轮没有改阈值或把失败改成通过。其余三项：总胜率52%（目标40—60%）、精英中位5回合（目标5—9）、认真防守探针净失血中位9（目标<20）通过。规则正确性门禁与这些体验指标分开报告。

另一项真实混杂是旧策略只认真评估S01—S16，后加S17—S36往往按低价值处理，忽略御剑和剑阵。这是自动策略缺陷，不等于游戏提供的新牌没用。对照策略现在会按实际规则预览评价新剑术、持续收益和商店/奖励选择；默认旧策略保留，便于复现。另修复探针在御剑回合末已击杀敌人时仍试图执行敌方回合的断言错误，未改变游戏结算。

## 任务感知配对实验

四组均使用同一50个种子、相同入魔/救人选择。全部通过正常API走完整路线，不注入生命、牌组、奖励或任务标记。

任务策略：寻找相连休息/狐灯，生命至少75%才立约，至少55%才炼契；实际付费，优先补足所需交锋，满足条件领取九命铃。消耗节点和生命上限是真实成本。

|策略|做续灯任务|胜局|实际领取|实际消耗|
|---|---|---:|---:|---:|
|旧出牌/奖励策略|否|12/50|0|0|
|旧出牌/奖励策略|是|14/50|49|42|
|补齐新剑术评估|否|13/50|0|0|
|补齐新剑术评估|是|17/50|48|41|

与旧策略不做任务逐种子相比，完整新策略11局由败转胜、6局由胜转败，其余不变；净增加5胜，并不是每个种子都会受益。不同选路和出牌改变后续随机数与构筑，所以这是“策略组合”对照，不是同一场战斗凭空增减一枚复活的纯因果实验。

任务可完成，复活也确有用，但不能替代构筑。新策略加任务的17胜中，学魔修分支14/25、拒绝魔修分支3/25；纯正道剑修风险仍然明显。不能借合计34%刚好进入旧目标区间就宣称职业平衡完成。真实玩家会用更完整的规划，本策略也并非最优解；两者都尚未验证。

## 区分曲线、复活和资源影响

另在独立实验副本中，只恢复指定规则，不改成品：

- 当前救命任务规则和回春露不变，仅恢复旧敌人曲线：旧策略剑修18/50胜。
- 在上一实验上再恢复旧回春露：20/50胜。
- 完整旧版：31/50胜；当前成品旧策略不做任务：12/50胜。

这些结果说明曲线和回血经济都有影响，而取消旧版易得、每战重置的救命能力及其奖励池变化也不能忽略。不能把各组胜局简单相减，当作彼此独立的精确贡献；路线与随机过程存在交互。

还试验过“御寒敌人本回合新凝结的霜寒不立即消退”，保留两张技能凝成一层的要求。结果旧策略降至8/50，新策略加任务升至20/50，依赖策略且不稳定。该方案没有进入成品，没有把一次试验的最佳胜率当成改动依据。

## 实际修复：截止条件与过期付款

上一版只限制49段前立约，却仍允许玩家在第七境炼契；此时只能在70段取得镇境证明，已没有下一境领奖，付费没有意义。本版修复：

- 最迟在**第49段的相连休息或狐灯节点**立约，不保证当前路线一定有该节点。
- 最迟第59段炼契。
- 必须在第60段或之前取得炼契后的镇境胜利证明。
- 最迟第69段到达休息或狐灯领取。
- 错过期限明确显示“已错过本局办理时限”，不能再扣款推进。此前代价不退款；仍可放弃。不会为赶时限自动送证明或奖励。

回归验证第49段立约→50段镇境胜利→51段普通战→52段炼契→60段镇境→62段领取可完成。也检查61段才尝试炼契、70段才尝试领取均拒绝，资源和状态不变。浏览器检查对应按钮禁用及可见说明。
